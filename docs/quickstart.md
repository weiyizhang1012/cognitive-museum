# 快速开始

## 1. 建立自己的馆藏

下载仓库，用 `vault-template/` 建立一个新的 Obsidian Vault，或只取用需要的规则与模板。已有 Vault 应逐项查看后加入，不直接覆盖同名文件。

骨架里的索引是空白入口，模板是可选起点。你自己的记录保存在自己的 Vault 中，不需要提交到此公开仓库。

## 2. 配置运行环境

`${VAULT_ROOT}` 表示你的真实 Vault 路径。`${CAPTURE_BASKET}` 是可选收件篮。将它们替换为你自己的设置；不要把个人绝对路径、凭证或私密记录提交到公开仓库。

本地 AI 环境需要具有文件读取工具。规则引用保存在 `vault-template/AGENTS.md` 与小张 Prompt 中。使用项目环境时，可以将 `config/ChatGPT Project Instructions.md` 放入项目说明，添加 `project-reference/Museum Reference.md` 为规则来源。

项目参考提供规则，实际馆藏仍从真实 Vault 读取。仅有前台聊天记忆时，保持请求待取证。

## 3. 提出问题

- “只记录今天这段话。”
- “找一下我指定日期的记录。”
- “在这个时间段内，比较我对这个问题的理解。”
- “用这些旧笔记帮我组织一篇文章。”

你不需要点名馆员。范围不够明确时，小张提出一个最小范围；取得授权后实际读取，并给出出处与材料限制。

## 4. 前后台衔接

无本地读取能力的前台会生成查询请求。后台具有相关聊天读取能力时，你说“小张，查馆藏”即可取单，不必复制卡片。

只有在工具实际可用且已有直接发送授权时才进行跨聊天派发或回传。通道不可用时，结果先在后台交付，并保留待回传状态。每次使用的权限与工具能力以实际环境为准。

## 5. 决定是否保存

查询与讨论可以在对话中结束。想保留新的认识时，再查看保存清单并确认；写入后核对真实文件。查询不会为了登记完成而写账本。

先看 [虚构演示](../examples/README.md)，再在自己的环境中测试指定文件读取、受限主题查询及周期回顾。
